# 2026-07-22

Time to create our first version of the main app. I am thinking tdt-explore for an entry point. The key to this design will be modularity, we want the user to compose exactly the information they want for whatever their current task is.

for important information about tdt data structures, I refer you to example one-off ephyviewer scripts for tdt available at `/c/Users/MBO/Documents/GitHub/tss-pipeline/scripts/visualization/tdt_data_viz` (more recently modified -> more relevant) Additionally, you can browse "C:\Users\MBO\Documents\GitHub\tdt-ephyviewer-explorer\docs\assets\SynapseManual.pdf" for in-depth information about Synapse, the program that saves the data structures.

Broadly, I am envisioning a two part GUI, a per-tank control window where we use pyqtgraph parameter trees backed by hydra config files to orchestrate what sorts of ephyviewer windows we want to see. Then, one or more per-dataset windows that actually display the data; this is where examples from `/c/Users/MBO/Documents/GitHub/tss-pipeline/scripts/visualization/tdt_data_viz` are relevant. In the control window, I pass a tank directory and it populates a list of plottable data structures (do some exploration on what the types of data structure are; for now, I am envisioning two main ones: continuous time series and events such as stimulation timestamps and metadata). To one or more of these, I can attach, e.g. ephyviewer.TraceViewers, or ephyviewer.EventList as appropriate. Any config of the ephyviewer widgets can be loaded from hydra configs, located at `/c/Users/MBO/Documents/GitHub/tdt-ephyviewer-explorer/src/config`.

If we need to save any persistent information, it's ok to create e.g. a 'tdt_explore' subfolder in the tank dir, but let's not pollute the dataset directories. They are for raw data only.

Features to be mindful of:
- data stream delays: for example, electrical stimulation timestamps from, e.g. eS1p gizmos, are delayed by a fixed number of samples wrt to the time series, and the time series can be delayed wrt to each other. these should be settable parameters in the controller and applied when a viewer is launched
- stim info ingestion: one of the hydra configs should control how raw stim metadata is converted to event view labels, as in the chan_formatter mechanism.
- for timeseries data streams, I want to be able to indicate probeinterface probe files such as "C:\Users\MBO\.torpedo\probe_maps\tdt_64ch.json" that trigger a reordering of channels into probe-native order. We'll need to add probeinterface as a dependency.
- 
Non-goal for now: tss-pipeline creates .parquet files that represent either processed time series or epoched data from tdt recordings. for now we are building the tool to visualize the raw data, no preprocessing needed.
